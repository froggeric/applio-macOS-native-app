# Applio Accessibility Audit — Blind / Screen-Reader Users

**Date:** 2026-08-21 · **Scope:** upstream Gradio web app (`app.py`, `tabs/`, `core.py`) + fork native wrapper (`applio_launcher.py`, `macos_wrapper.py`, `menu_spec.py`, `assets/loading.html`) + the pywebview/WKWebView boundary · **Method:** 17-agent workflow (4 mappers, 6 dimension auditors, 6 adversarial verifiers, 1 completeness critic); every finding was independently re-verified against the code and against the *installed* Gradio 6.20.0 / pywebview 6.2.1 bundles in `venv_macos`.

**Totals:** 75 findings — **8 blockers, 42 major, 25 minor** (56 verifier-confirmed, 19 adjusted, **0 refuted**) — plus 11 critic gaps, several potentially blocker-class. Full detail in Appendix A; research facts with sources in Appendix B.

---

## 1. Executive summary

A blind user cannot currently operate Applio end-to-end. The three load-bearing failures:

1. **Nothing is ever announced.** Zero `gr.Progress` in the repo; Gradio 6.20's status tracker itself has **zero ARIA** (verified in the installed bundle — no `aria-live`, no `role=progressbar`); every long action blocks and returns one final string into a textbox that has no live-region semantics. The only announced channel Gradio offers — `gr.Info`/`gr.Warning`/`gr.Error` toasts (`role=status aria-live=polite`) — is used for trivia while outcomes go to silent textboxes. On the native side, the announcement helper `_announce_for_accessibility` exists but is called at exactly 4 sites, all inside `ProgressWindowController`, a window that only appears when the app *relaunches* with already-running jobs. The in-session Process Dashboard never announces; there is no dock badge, no `requestUserAttention`, no sound anywhere.
2. **File/path input is memory-only.** 10+ server-side path inputs are bare `gr.Textbox`es with no browse affordance; dataset path is a combobox of relative dirs validated only after submit (no `expanduser`, so `~/...` fails); dropdown choices are raw relative file paths (screen-reader-verbose); the native menu offers no pick command; and no JS→native bridge exists (`webview.create_window` passes no `js_api`). Upload drop-zones ARE keyboard-operable and open the OS dialog — but their labels say "Drag and drop…", actively pointing blind users away from the working route.
3. **The webview boundary silently strips accessibility.** pywebview's cocoa layer empties the native context menu (`removeAllItems`), the fork suppresses the default Edit menu, `WKPreferences.tabFocusesLinks` is never enabled (default **False** → Tab cannot reach any button), `ALLOW_DOWNLOADS` is never set (gr.File download links — e.g. exporting the trained model — are **silently cancelled**), and there is no content zoom. In a browser the upstream app gets all of this for free; in the wrapper it is removed. The completeness critic flagged this seam as the audit's systematically under-examined layer, alongside **journey completion** (export → dead link; report a bug → screen-recording only; update → teleport to GitHub; restart → silent `os.execl`).

Offsetting good news (verified positives, do not re-fix): Gradio 6.20 dropdowns have full combobox semantics (fixed by gradio PR #13542, which was filed by a **blind Applio user** — issue #12855); toasts are announced; `gr.File`/`gr.Audio` drop zones are keyboard-activatable and open the native open-panel; sliders render native `<input type=range>`; `gr.Tabs` render proper `tablist`/`tab` semantics; VoiceOver CAN traverse the WKWebView `AXWebArea`; dock-click restores a hidden window.

## 4. Critic gaps (not covered by the 6 dimensions — several potentially blocker-class)

1. **Clipboard/context menu possibly dead app-wide**: pywebview empties the WKWebView context menu (cocoa.py:508-510, debug=False) AND the fork suppresses the Edit menu (`SHOW_DEFAULT_MENUS=False`) — the only remaining path is pywebview's keyDown shim calling an `NSText`-only API on `WKContentView`. Blind users paste long paths constantly. **Decision-critical live test.** Wrapper fix: add an Edit menu (`cut:`/`copy:`/`paste:`/`selectAll:`) to `menu_spec.py` + both renderers.
2. **Export dead end**: `ALLOW_DOWNLOADS` never set → gr.File download links (trained `.pth`/`.index`, F0 txt) are silently cancelled. One wrapper line + announcement.
3. **Realtime mic likely broken outright**: `NSMicrophoneUsageDescription` was removed from Info.plist (stale two-process-era rationale, build_macos.py:1073) but realtime capture is now in-process (`rvc/realtime/audio.py` `sd.InputStream`) — macOS will auto-deny. Functional regression, not just a11y.
4. **10-second toasts, no message history**: every `gr.Info/Warning/Error` auto-dismisses (gradio default `duration=10`, no call site overrides); a missed announcement is gone forever. Route job-critical outcomes to a persistent, announced "Last result" region.
5. **Native surfaces are English-only**: menu, dashboard, dialogs, announcements bypass the 50-language i18n system — must be wired into `assets/i18n` as part of any announcement work.
6. **External-context handoffs are unannounced teleports**: terms-of-use links, Help items, Reveal-in-Finder jump VoiceOver into another app with no warning/return path.
7. **Report-a-bug journey is screen-recording-only** — meaningless for blind users; add a diagnostics/log-bundle button.
8. **Update journey dead-ends in a browser**: "Download Update" just runs `open <releases URL>`; renaming + accessible instructions or in-app download needed.
9. **"Restart Applio" settings button `os.execl`s the whole single process** with no confirmation, no announcement, orphaning running jobs.
10. **Braille displays never considered**: glyph bars, 0.1–2 s value churn, and unsegmented announcements are hostile to refreshable braille; the announcement architecture must budget for braille cadence/length.
11. **No content zoom** anywhere in the native app (low-vision), unlike every browser.

## 5. Improvement strategy — the three vectors, combined

The vectors are complementary; almost every top fix uses more than one. Assessment:

### [W] Native wrapper (fork-owned files) — highest leverage per effort
Everything in `applio_launcher.py` / `macos_wrapper.py` / `menu_spec.py` / `assets/loading.html` is ours to fix with zero upstream-delta cost:
- **Announcement architecture** (ir-4, the enabler for ps-2/3, na-1, ir-3/5): a fork-owned `applio_a11y.py` — gate on `isVoiceOverEnabled()`, coalesce (phase changes + terminal states + ≥10 % milestones, min 5 s apart; never per-tick), post from `self.window` (focused-element ancestor rule), mirror to braille by nature, optional `NSSound` cue channel; an **Accessibility submenu** (Announcements: Off/Standard/Verbose; Sound cues) persisted in NSUserDefaults. Wire it into `transition_to_active/idle`, `update_process_list`'s 2 s heartbeat (which already runs with the dashboard closed), `stopProcess_`/`togglePauseProcess_`, `_render_inference_detail` terminal changes, and `_surface_window`.
- **Completion cues** (ps-3/na-2, S): `NSApp.requestUserAttention_` on terminal transitions, `dockTile().badgeLabel_` = running-job count, cleared on idle; distinguish failed/completed from `process_history.json`.
- **Webview boundary repairs** (kf-1/ir-2, R4): `setTabFocusesLinks_(True)` on the WKWebView after first navigation (via `_reassert_menu_and_delegate`); `webview.settings['ALLOW_DOWNLOADS']=True`; add an Edit menu; optionally override pywebview's open-panel delegate to honor the directory flag (fs-3); consider `NSAccessibilityLayoutChangedNotification` at the loading→Gradio swap (ir-10).
- **Boot experience** (ps-4/ws-2/ir-1, S): fork-owned `loading.html` — static `aria-live=polite` status region + `role=progressbar` with `aria-valuenow` on `#progress-bar`, stage-transition announcements only; drive `window.set_title("Applio — <stage>")`; convert the two silent failure paths to NSAlert + announcement; `prefers-reduced-motion` CSS.
- **Dashboard truth-telling** (ps-9/na-4/5/6/7, S–M): pair every `setTitle_` with `setAccessibilityLabel_`; `setAccessibilityValue_` on progress/chart ("Epoch 34 of 200, best loss 0.123, ETA 41 min"); inference-specific labels; spell out row states ("Completed — Training: x" vs `✓`); update the status badge; flatten the progress-window live zone into one summary element; hide the Unicode bar from the AX tree.
- **First-run flow** (ir-6, S): confirm-dialog + re-pick on Cancel, announce the outcome; add `NSMicrophoneUsageDescription` back.
- **Menus & dialogs** (kf-7/na-12, kf-8/ir-11, S): shortcuts for logs (`⌘L`), data location, show-main, reveals (all Cmd-modified, clear of VO keys); `setInitialFirstResponder_` + key-view loop on dashboard/progress windows; make destructive "Terminate & Quit" non-default; `activateIgnoringOtherApps_` + Escape-bindable Cancel on update alerts; enable the `process.status` menu item (verify VO traversal of disabled items first).

### [P] Build-time patches — one injection point, coarse anchors only
The maps confirmed two stable anchors in `app.py` (upstream-owned but already patched by us):
- **`js=`/`css=` launch kwargs (app.py:227-241, GRADIO_6 branch — `css=` is already passed unconditionally)**: inject one fork-owned a11y JS payload (ship as a data asset, like `tabs/realtime/main.js`): create a global `aria-live=polite` region; heal accordions (`aria-expanded` on `button.label-wrap`); announce output-textbox mutations; restore focus after start/stop swaps; add `aria-pressed` on record toggles; restore `:focus-visible` outlines for checkboxes/radios; add `alt` from block labels onto `<img>`; optionally announce conditional reveals.
- **FastAPI route injection (anchor: the TensorBoard proxy, app.py:249-279)**: a `/api/progress` route serving `active_processes.json` + `inference_progress.json` + parsed training metrics (data already computed by `applio_inference_stats` / `process_log_parser`); the JS polls it every ~2 s and announces phase changes/milestones/completion. This makes the **web UI itself** announce progress for every job type, including training (where a Python-side `gr.Progress` patch can't work because handlers block on `_proc.wait()`).
- **Per-component constructor rewrites are proven feasible** (`patch_train_44100.py` rewrites a `gr.Radio(choices=…)` in place) but each anchor breaks on upstream sync — reserve them for high-value cases (labels on the 4 unlabeled components, tuple choices for path dropdowns, `elem_id`s for Browse-button targeting, uncommenting the Stop `gr.Info`s) and prefer upstream PRs otherwise.

### [U] Upstream PRs — two targets, real precedent
- **IAHispano/Applio** (cross-platform by construction — anything using Gradio APIs works in browsers): route outcomes through `gr.Info`/`gr.Error` (announced) instead of silent textbox strings (ws-1, ps-7); `gr.Progress(track_tqdm)` / default-param injection for batch inference (ps-8 — verifier note: `gr.Progress` is detected via a **default parameter value**, gradio/helpers.py:979); start/end `gr.Info` for training/prerequisites/downloads (ps-10/12/13); tuple `(label, value)` dropdown choices (fs-4); relabel "Drag and drop…" instructions (fs-7); disambiguate duplicate labels (ws-10); headings in large tabs (ws-9); i18n the ~20 hardcoded enforcement/error/status strings (ws-13); fix the **batch-formant wiring bug** (ws-4) and the iframe title (ws-11); the reported `return gr.Warning(...)` at download.py:134 actually renders (side-effect call) — the raisable class is `gr.Error`.
- **gradio/gradio** (maintainers merge well-scoped a11y PRs: #2777 aria-labels on icon buttons, #13542 combobox fix…): the **status tracker ARIA gap has no open issue** — a PR adding `role=progressbar` + `aria-valuenow/valuetext` + throttled `aria-live=polite` on progress-text is novel, high-value, and backed by our bundle-level evidence; accordion `aria-expanded`/`aria-controls` (ws-3/kf-5); `<img alt>` propagation for `gr.Image` (ws-7); WAI-ARIA tabs keyboard pattern (kf-9); checkbox/radio `:focus-visible` outline restoration (kf-11). Filing #12855-adjacent issues links this work to an existing blind Applio user's report.

## 6. Phased roadmap

**Phase 0 — live VoiceOver validation (decision-critical, before investing):** on `dist/Applio.app`, with VoiceOver on: (1) clipboard reality check — `⌘C/⌘V/⌘A` in a Gradio Textbox, `VO+Shift+M`, menu-bar Copy/Paste (decides the Edit-menu cluster's severity); (2) train→finish→export round trip — does the `.pth` export link do ANYTHING (`ALLOW_DOWNLOADS`); (3) realtime Start with a mic (TCC denial vs removed usage description); (4) boot end-to-end — readiness signal, AX state after the loading→Gradio swap, the 10 s-later update alert; (5) toast catching during a long job; (6) repeat 1+4 with a braille display. Sessions 1–3 can each reveal a fully-blocked journey.

**Phase 1 — wrapper quick wins (days, all fork-owned):** dock badge + `requestUserAttention` + announcement coalescer wired to dashboard transitions (ps-2/3, na-1/2); `setTabFocusesLinks_(True)`; `ALLOW_DOWNLOADS=True`; Edit menu; loading.html ARIA + `set_title` + reduce-motion; Pause-label/status-badge/history-`✓`/inference-label truth fixes; destructive-default reorder; update-alert activation + Cancel; `NSMicrophoneUsageDescription`; menu shortcuts; first-run confirm dialog. Also patch-side one-liners: uncomment Stop `gr.Info`s, `gr.Info` on uploads/exports.

**Phase 2 — the a11y injection + pickers (1–2 weeks):** `/api/progress` route + JS live-region payload (web-side announcements for all jobs); `js_api=FileBridge` + per-field Browse buttons for the ~10 path fields (+ `expanduser`/on-change validation, dataset folder picker); Accessibility settings submenu (verbosity/sound/braille cadence); i18n plumbing for native strings; persistent "Last result" region (10 s toast problem); error surfacing with log tails.

**Phase 3 — upstream:** Applio PRs (error/toast routing, `gr.Progress` for batch inference, tuple choices, labels/headings, i18n, wiring bug) and gradio PRs (statustracker ARIA first — novel and evidence-backed). Each merged PR shrinks the fork's patch surface.

- **[high] WAI-ARIA pattern: role=progressbar** — role=progressbar (MDN/W3C ARIA 1.2): (1) accessible name REQUIRED (aria-label or aria-labelledby — on native <progress>, a <label>); (2) aria-valuenow REQUIRED when determinate, must be kept updated; OMIT it entirely for indeterminate bars; (3) aria-valuemin/valuemax optional, default 0/100; (4) aria-valuetext when a percentage would mislead — e.g. '3 of 10 files uploaded' or 'epoch 34 of 200'; (5) descendants are flattened to presentation — put no semantics inside; (6) for the surrounding region, best practice is aria-busy=true during load + aria-describedby pointing at the status text; (7) native <progress> preferred over the ARIA role when possible. This is the exact template an [upstream] gradio PR or an Applio-injected (elem_id-targeted) markup fix should follow. [source](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/progressbar_role)
- **[high] WAI-ARIA pattern: live regions (polite vs assertive) and status** — aria-live values (MDN): 'off' (default — updates announced ONLY if focus is inside the region), 'polite' (announce at next graceful opportunity, queues behind current speech — the right choice for job progress/completion), 'assertive' (immediate, may FLUSH queued polite announcements — reserve for urgent errors). role=status implicitly = polite (gradio toasts correctly use it); role=alert implicitly = assertive. Live regions include descendants; value inherited from nearest ancestor. Best practices that map 1:1 onto Applio's needs: create the region empty up-front then inject text (regions added AFTER the accessibility tree is built may be missed — relevant for the dynamically-swapped Gradio tabs and for the WKWebView desync bug); keep announcements brief; for CONTINUOUSLY updating widgets use aria-live=off and let users read on demand, or coalesce rapid updates behind aria-busy to prevent a flood of queued speech (a per-epoch announcement would be hostile; announce phase changes + completion + milestones instead). [source](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-live)

**Single-conversion tracking (`bc96c58a`)** — the resilient, SSE-independent fix the repro
verdict (previous subsection) prescribed. `patch_inference_progress.py` now also wraps
`VoiceConverter.convert_audio`'s body between two stable endpoints (after `self.get_vc(...)`,
before the `elapsed_time` tail): `_infer_single_begin`/`_infer_single_end` write a
`scope: "single"` start record and a terminal record (completed/error, total 1) into
`inference_progress.json` plus a schema-compatible history row — so the menu, dashboard, and
a11y payload show a running single conversion even when no toast stream is live, a crash-orphaned
record is swept to "interrupted" at next launch (same as batch), and the a11y terminal words
cover single runs. Tracking failures are swallowed — conversion can never be broken by tracking.
**Batch guard:** any existing record with status running/cancelling and `scope != "single"`
skips ALL single writes (start and terminal) — one atomic-write owner at a time; batch records
carry no `scope` key, so the same guard makes the batch loop's per-file `convert_audio` calls
tracking no-ops. Reviewer-noted behaviors, both accepted: (1) **TTS runs funnel through
`convert_audio`**, so their convert phase logs an inference-typed progress record + history row —
cosmetic cross-labeling, accepted; (2) **the dashboard Stop is a no-op for a running SINGLE** —
the cancel flag is checked only in the batch loop.

**allowed_paths (`16c72f86`)** — the built app's converted outputs existed on disk but never
loaded in the UI: gradio serves output files only from its allowed set (cwd + temp), and the
frozen cwd is the bundle → `InvalidPathError` in postprocess. `patch_progress_routes.py` rides
its existing launch-kwarg anchor with `allowed_paths` resolved at LAUNCH time: **frozen** =
`APPLIO_DATA_PATH` (set in-process by macos_wrapper before Gradio) + `~`; **dev** = `~` (the
unset env entry is `if p`-filtered — gradio's `abspath` stringifies a raw None into a bogus
`<cwd>/None` entry; the filter is hygiene against that, not a crash guard). **Security decision,
recorded:** allowing `~` lets the 127.0.0.1-bound gradio server serve any file under the user's
home to local clients — accepted trust domain because the files at issue are picked by the user
via the native NSOpenPanel; whitelisting `/` was rejected (gradio would serve any local file).
**Residual:** input audio browsed from outside `~` (e.g. an external volume) still writes its
output outside the allowed set → unserved; the nontrivial follow-up is a per-session allowlist
of picker-chosen directories.
